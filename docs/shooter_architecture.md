# ROX2026 ベルトシューター（射出機構）アーキテクチャ設計書

## 1. 概要
本プロジェクトでは、2基のMAD Motorとベルト機構（またはローラー機構）で弾を挟み込んで射出する方式を採用します。
ROS 2からは直接モーターを駆動するのではなく、STM32（モータードライバ）に対してCANバス経由で指令を送ります。

## 2. 制御方式（絶対的ルール）

**❌ オープンループ制御（PWM指定）は禁止**
ROS 2から「PWM値（0〜255等）」を直接指定する設計は行わないでください。バッテリー電圧の低下に伴い、同じPWM値でもモーターの回転数が落ちるため、試合後半で自動照準が狂ってしまいます。

**⭕ クローズドループ制御（速度制御・RPM指定）を推奨**
ROS 2からは「目標回転数（RPM）」または「目標角速度（rad/s）」をCANで送信してください。
STM32側（またはESC）でエンコーダの値を読み取り、ハードウェアPID制御を行って指定されたRPMを維持するように実装します。これにより、電圧低下に関係なく常に一定の飛距離を担保できます。

## 3. ROS 2 ノードアーキテクチャ

自動運転（Auto Strategy）と手動操作（Teleop）が競合しないよう、**Shooter Mux（優先度付きルーティング）**を導入しています。

### ノード構成
1. **`shooter_teleop_node`**:
   - 役割: Joy（コントローラー）の入力を読み取り、目標RPM（または段階的な速度モード）を計算します。
   - 出力: `/shooter/cmd_joy` (std_msgs/Float64) ※単位: 目標RPM
   - 特記: デッドマンスイッチ（L2など）が離された場合は、必ず `0.0` を出力して安全に停止させます。
2. **`auto_strategy_node`**:
   - 役割: カメラやLiDARからのターゲット距離を元に、最適な射出RPMを計算します。
   - 出力: `/shooter/cmd_auto` (std_msgs/Float64)
3. **`shooter_mux`**:
   - 役割: TeleopとAutoの指令を切り替えます（基本は手動操作が優先、一定時間入力がなければ自動運転の指令をパススルー）。
   - 出力: `/shooter/cmd_muxed` (std_msgs/Float64)
4. **`mad_motor_driver` (CANブリッジ)**:
   - 役割: `/shooter/cmd_muxed` をサブスクライブし、CANのフレームフォーマットに変換してSTM32に送信します。

## 4. 自動運転におけるRPMの計算（多項式近似）

物理法則（放物線の公式）からの逆算は、空気抵抗やベルトの滑りにより現実の飛距離とズレが生じます。
実機でターゲット距離に対する最適なRPMを計測し、**近似曲線（カーブフィッティング）**を用いてRPMを算出してください。

**計算例 (2次関数の場合):**
```python
# target_distance: カメラやOdomから得た目標までの距離 [m]
# A, B, C: 実機計測データから算出した係数
target_rpm = A * (target_distance ** 2) + B * target_distance + C
```

## 5. 安全対策（フェイルセーフ）
- **デッドマンスイッチ**: コントローラーの有効化ボタン（L2など）が離された場合は即座にRPM=0を出力する。
- **タイムアウト**: `/shooter/cmd_muxed` の更新が一定時間（例: 0.5秒）途絶えた場合、`mad_motor_driver` は自動的にモーターを停止させるウォッチドッグを実装する。
- **物理E-Stop**: STM32やモーターの主電源ラインに、非常停止ボタンを物理的に直列に接続すること。
